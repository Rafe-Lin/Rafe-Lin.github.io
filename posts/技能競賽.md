#### 子題 5 
- `Message signing enabled but not required。`
- 意義：SMB（伺服器訊息區塊，即檔案分享服務）雖然支援「數位簽章」，但並不強制要求。
- 風險：這會導致系統容易遭受 「中間人攻擊」(Man-in-the-Middle, MitM)，攻擊者可以攔截並修改傳輸中的檔案資料。
- 修復目標：將 SMB 簽章從「啟用（可選）」改為「永遠要求（強制）」。
正確項目： Microsoft 網路伺服器: 數位簽署通訊 (永遠)
- 正確設定值： 已啟用 (Enabled)
- 電腦設定 > Windows 設定 > 安全性設定 > 本機原則 > 安全性選項

#### 子題 7
- facl（Filesystem Access Control List，檔案存取控制清單）
- 練習時要先自己建立目標
- 傳統的 chmod 只能針對 擁有者 (Owner)、群組 (Group) 與 其他人 (Others) 做設定，但題目要求「只針對 webadmin 一個人」進行限制，這就是 `facl`
- 要限制 ssh 指令，首先要找到它存在哪裡。`which ssh`，通常會回傳 /usr/bin/ssh。
- `sudo setfacl -m u:webadmin:--- /usr/bin/ssh`
`setfacl`：設定檔案存取控制清單。
`-m`：代表 modify (修改)，用來新增或變更權限。
`u:webadmin:---`：針對 u (user) 使用者 webadmin 給予 --- (無權限)。
- `getfacl /usr/bin/ssh` 確認

#### 子題 8
- 管理誰可以使用 sudo 的核心檔案是 /etc/sudoers。但絕對不要直接用 vi 或 nano 開啟它，因為一旦語法寫錯，整台系統的 sudo 功能可能會掛掉。

1. 使用正確的工具：visudo
邏輯： visudo 會在存檔前自動檢查語法，如果寫錯了它會警告你，這是比賽中避免低級錯誤的保險。

操作： 使用原本具備 sudo 權限的帳號（題目提供的 deff），輸入： sudo visudo

2. 理解語法結構
你需要在檔案末尾新增一行，其邏輯結構如下： 使用者 登入主機=(執行身份) 指令路徑

使用者： webadmin

登入主機： ALL（代表從任何地方登入都適用）。

執行身份： (ALL:ALL)（代表可以模擬任何使用者或群組身份）。

指令路徑： /usr/bin/ssh（務必使用絕對路徑，可先用 which ssh 確認）。

因此，你要加入的那一行是： webadmin ALL=(ALL:ALL) /usr/bin/ssh

- 驗證成功 
你需要展示從一般使用者切換為 webadmin，並成功使用 sudo 的過程。 指令順序如下：

`su - webadmin` (切換使用者) 密:`password`
`sudo ssh localhost` (嘗試以 sudo 執行 ssh)

#### 子題 9
- iptables 是控制進出流量的最基本工具。要禁止 Ping，本質上就是禁止 ICMP 協定的 echo-request 封包。
iptables 就像是主機的門神，規則由上而下執行。我們要針對「進入」這台主機（lyonus）的封包做過濾。
 `sudo iptables -A INPUT -p icmp --icmp-type echo-request -j REJECT`

`-A INPUT`：在 INPUT 鍊（進入主機的流量）中 Append (新增) 一條規則。

`-p icmp`：指定協定為 ICMP。

`--icmp-type echo-request`：精確鎖定 Ping 的「請求」封包。

`-j REJECT`：拒絕。
